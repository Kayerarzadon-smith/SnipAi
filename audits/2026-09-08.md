# SnipAi audit — 8 September 2026

**Scope:** the whole repo — the Next.js app, `lib/`, the Swift wrapper, the
Python/ffmpeg pipeline in `ugc-edit-system/`, and every shell script.
~10,800 lines of source across 136 files.

**Headline:** the pipeline is in good shape; the app has drifted. The
three-level review flow that is the entire premise of SnipAi is the
least-finished thing in the repo, while a multi-track editor, a motion-graphics
compositor and a connectors page got built around it. Two defects are degrading
your output *right now*: a learned parameter has been poisoned to 88× its
intended value, and the undo path silently deletes every hole, fade and detached
audio range in a project.

Line numbers below are from the working tree at the time of the audit. You had
uncommitted edits in `Timeline.tsx`, `review/page.tsx` and `timelineLayout.ts`
while this ran, so a few may have shifted by a line or two.

---

## Fix these first

1. **`ugc-edit-system/state/tuning.json` → `"snap_tail": 0.881`.** Reset it to
   `0.01`. The intended range is 0–0.05s. `build_cut.py:227` applies it as
   `e = max(x + snap_tail, s + 0.05)` with no clamp back to the original end, so
   every beat that ends near a silence is being *extended* 0.88s into the pause —
   the exact dead air the snapper exists to remove. On a 22-beat video that is
   ~15 seconds of added pause. `learn_from_edits.py:282` has no upper bound and
   auto-applies on three examples, so it will do it again.
2. **`app/api/projects/[project]/pipeline/route.ts:136–157`.** ⌘Z and
   "restore deleted line" both PATCH here, and the handler rebuilds each beat
   from a four-field whitelist. Every `holes`, `audioStart`/`audioEnd`,
   `fadeIn`/`fadeOut` in the project is dropped on the next undo. The comment
   above it says an unchecked write would corrupt the edit; the validation *is*
   the corruption.
3. **`lib/jobs.ts:184` — `failJob()` never calls `persist()`.** Every sibling
   mutator does. A failed build stays `running` in `jobs.json` forever, the UI
   spins with no error, and `graphics/route.ts:137` then returns 409
   "already running build" until you restart the server.
4. **Three live entry points call tools that moved to `tools/_superseded/`.**
   `process_inbox.sh:32` (→ `auto_edit.py`), `build-v7.command:5`
   (→ `tune_and_build.py`), and `CLAUDE.md:60,97` (→ `scan_source_takes.py`,
   `scan_output.py`). The drop-folder watcher you installed as a LaunchAgent is
   dead on arrival, and the two most load-bearing rules in your method doc point
   Claude Code at files that aren't there.
5. **`scripts/test` prints "all green" while skipping the entire Python suite.**
   A skip should not read as a pass. *Correction to the first version of this
   report:* the venv is not broken. `bin/python` is a symlink out to a system
   framework, which is unreachable from the sandbox this audit ran in but fine
   on the Mac itself — `lib/paths.ts:30` already documents and resolves around
   it. The defect is the reporting, not the detection: fix the summary line,
   don't "fix" the check into calling a working install broken.

## Bloat — works, but worth questioning

**The timeline editor** (`Timeline.tsx` 800 lines + `timelineLayout.ts` 216 +
`TrimWave.tsx` 421, and ~a third of the client code). NOTES.md asks Level 2 for
"scrub the timeline and mark roughly where it's wrong — *no detailed diagnosis
required yet*". What exists is a two-track NLE: five zoom levels, drag-to-reorder,
drag-to-trim, corner fades, a detachable audio track, span marking, a waveform
canvas, per-window filmstrips, scrub audition, and its own shortcut sheet. It's
why `review/page.tsx` is 2,180 lines with 30+ `useState` hooks, and it's what
generates the `trimEdits` that poisoned `snap_tail`.

The argument against it is your own: CLAUDE.md §5 is an extended case that pads
must be computed off word gaps rather than eyeballed. Hand-dragging an edge
produces a one-off fix the pipeline can't generalise — the workflow NOTES.md set
out to replace. *Keep* span-delete and the `[`/`]` nudge. *Question hard:*
reorder, fades, detached audio (broken anyway), five zoom levels.

**The graphics subsystem** (~1,300 lines across `GraphicsPanel.tsx`,
`graphics/route.ts`, `plan_graphics.py`, `motion_graphics.py`,
`find_overlay_cues.py`). `CLAUDE.md:30`, measured off your reference pair, says:
"**No captions, no graphic overlays, no PIP.** Hard cuts only, real background."
The feature builds elaborate tooling to produce output your style guide forbids.
It costs a second Whisper pass, a second full render, a glossary that doesn't
ship, and its own job type. Fair counterpoint: if the house style has moved on,
`CLAUDE.md:30` is the stale artifact. But one of the two is wrong and both are
live.

**The `.command` fleet** — nine scripts. Three are broken or point at the wrong
directory; the rest are one-time bootstrap for one Mac. They're the first thing
anyone opens, and half of them fail. Collapse to `setup.command` +
`launch-snipai.command`.

**The drop-folder watcher**, conceptually — even repaired, it's a second ingest
path that bypasses review entirely: video in, auto-edit, finished file out,
notification. That's the no-decision-queue workflow SnipAi exists to replace, and
`DropZone.tsx` already ingests properly. Delete rather than fix.

**Four independent undo mechanisms** for a single user editing one JSON file:
60 snapshots per project, a 5-day `.trash/` with a dashboard section, an in-page
history stack, and the delete toast. `KEEP = 60` is generous for a workflow whose
goal is "most videos should end at Level 1".

**Settings has five tabs**; two earn it (Editing preferences, Style references),
one is useful (Pipeline availability), one feeds nothing (Products), and Profile
is a hardcoded `<div>Kayer · Arzacorp</div>` plus a mic test.

## Method

Free tools first: `tsc --noEmit` (clean), the repo's own 72 tests (all pass —
but the Python suite silently skips), and `knip` for unused files/exports/deps,
which crashed with `RangeError: Array buffer allocation failed` — your startup
disk is at 100% with ~1.4GB free, which is also worth fixing on its own.

Then four parallel Opus reviewers over the whole tree — server, client, pipeline,
and a bloat sweep against NOTES.md — followed by a verification pass in which
every top finding was re-opened at its cited line. I personally confirmed
Fixes 1–5 and C1, C2, C3, the `audio.sh` orphan, the Level 1/Level 2 gaps and the
five uninvoked Python tools against the live files. The remainder are
line-anchored reports I did not individually re-open.

Every finding here now has an id and a row in `audits/LEDGER.md`, which is the
live state; this report is the snapshot of the day it was written. Re-runnable
as `./scripts/qa` and `/qa` in Claude Code; `/qa-fix <ids>` works through them.
