# SnipAi QA ledger

**Scope: the SnipAi app** — `app/`, `lib/`, `native/`, `scripts/`, `tests/`,
root config. The `ugc-edit-system/` pipeline is out of scope; findings already
made there are kept at the bottom for reference and are not worked on unless
asked (`./scripts/qa --with-pipeline` re-enables its checks).

Every finding QA has confirmed, and what happened to it. This file is the
memory between runs — `/qa` reads it before reporting so it tells you what is
*new* instead of repeating itself, and updates it after.

**Status:** `open` · `fixed` (with date) · `wontfix` (a decision, not an
oversight) · `regressed` (was fixed, came back).
**Test:** the regression test that reproduces it. A test here that starts
passing means the bug is fixed — that is the signal to flip the row.

Run `./scripts/qa --regressions` to see the bug board. Run `/qa-fix S1 S2` to
work through them.

**How rows are counted — one definition, settled 2026-09-10.** Two different
totals were circulating, which is how a ledger stops being trusted. The number
anyone quotes is the **finish-line count**: live rows (`open` + `regressed`,
excluding `fixed`, `wontfix` and `retired`) in **Server, Client, Native and
shell, Tooling, and the two Edit-quality sections** — the sections that stand
between the app and shipping. **Unused (U), Half-built (H), Bloat (B) and Repo
hygiene (G) are excluded**: each is its own milestone (M3, M4, M5) or its own
role's checklist, and folding them in inflates the number that is supposed to
mean "defects left". Pipeline (P) is quoted separately, never folded in. The
earlier "69" was every live row in the file; it was not wrong arithmetic, it
was the wrong denominator, and the finish-line count is the one that governs. **One more number exists and is not a rival:** `guard-ledger.py` prints *"N row(s) marked open or regressed have no test on the board"* (93 today) and labels it, in its own output and in a comment, as **not** the defect count — it counts every live row in the file, U/H/B/G and pipeline included, and only says which have no board test. Dev added that disclaimer deliberately so a script could not undo this rule. Quote the finish-line count; quote 93 only as coverage.

**Rows are not milestones — settled 2026-09-11, the second definitional rule
this file has needed and from the same confusion as the first.** A row tracks
a **code defect**: it is `fixed` when the code is fixed and its test is green.
A milestone tracks a **verified outcome**: it closes when the role that can
verify it says so. "Merged but not shipped" is a state a row has never been
able to express and should not have to — it belongs in the milestone's exit
line. If an artifact check later shows the fix did not reach the app, the row
goes **`regressed`**, which is exactly what that status is for.

Both halves of the confusion bit within one session. **M0.6 was closed on a
merge** — a milestone taking a row's word for a verified outcome. Then
`./scripts/bundle-app` **deadlocked**: `guard-ledger` blocked the rebundle
because N1's row was open, and N1's row was open pending the rebundle — a row
being asked to carry an artifact's status. Opposite directions, one error. The
guard's contract, "test green ↔ row fixed", was sound throughout and was not
weakened to resolve it.
